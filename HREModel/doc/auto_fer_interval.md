# 自动化确定 FER 区间与仿真点位（AWGN/TAWGN/ERR\_INJ）

本文给出一个“可落地”的自动化方案，用于在大量不同矩阵/码率/译码器/配置条件下，自动确定应当仿真的横轴区间与采样点位，使得每个条件组合的曲线能覆盖 $FER\approx 1$ 到 $FER\approx 10^{-6}$ 的主要区域，同时尽量减少冗余点与无效计算。

本文的核心思想来自常见的 LDPC characterization 流程：**先用很小样本快速定位瀑布区窗口，再在窗口内逐轮加深曲线**；并在曲线两端使用“早停规则”避免浪费。

---

## 1. 背景与问题刻画

在实际 characterization 中，困难不是“怎么仿真一个点”，而是：

1. 不同矩阵码率、译码器实现、信道模型（含 HRE/TAWGN 等）会导致瀑布区位置不同，若对所有配置使用同一个大范围与固定步长（如 SNR 每 0.1 dB），会产生大量冗余点与无用 log。
2. $FER\approx 1$ 的“起点”无需精确，但需要一个稳健的工程判据，用于确定“低端窗口已经覆盖”。
3. 在 $FER\le 10^{-5}$ 的低误码区，仿真点往往更耗时；点位策略必须考虑计算预算，否则曲线会被高 SNR 的昂贵点拖死。

---

## 2. 统一输入/输出与术语

### 2.1 配置组合（case）

将一次 characterization 的“条件组合”抽象为 `case`：

- 矩阵/码率（matrix / rate）
- 译码器（decoder）
- 信道模型（AWGN / TAWGN(TRUNC\_AWGN) / ERR\_INJ）
- HRE bit（若适用，通常体现在目录 `0bit/1bit/...`）
- 其它配置（bin量化、迭代次数、阈值策略等）

建议为每个 `case` 定义一个稳定的 `case_id`（可由路径拼接或哈希得到），用于 manifest 追踪与去重。

### 2.2 横轴选择

- AWGN/TAWGN：横轴建议使用 `TheoRBER`（由信道参数计算的理论 RBER），原因是它比 SNR 更便于跨配置对齐。
- ERR\_INJ：横轴使用注入错误数 $K$（你已确认 ERR\_INJ 下不注入 HRE）。

注意：在你们的 C 模型中，仿真命令可能以 SNR 作为输入，但日志会打印 `TheoRBER`；因此脚本层可以“输入 SNR、记录 TheoRBER、最终以 TheoRBER 作图”。

### 2.3 目标区间

目标覆盖的 FER 区间设为：

- 高端：$FER \ge FER_\text{hi}$，推荐 $FER_\text{hi}=0.9$（工程上视为“接近 1”）
- 低端：$FER \le FER_\text{lo}$，推荐 $FER_\text{lo}=10^{-6}$

你也可以按需求改成 $10^{-5}$ 或 $10^{-7}$。

---

## 3. 总体流程（两阶段 + 多轮）

对每个 `case`，流程为：

1. **第 0 轮（pilot）**：用小样本 + 粗步长快速定位“有效窗口” $[x_\text{low}, x_\text{high}]$，其中横轴 $x$ 为 TheoRBER（或 SNR）/K。
2. **第 1..L 轮（refine）**：只在窗口内布点，并逐轮增加每点样本量，向低 FER 推进；同时按规则调整步长（例如当 $FER\le 10^{-5}$ 时加密到 0.05/0.025）。
3. **写 manifest**：记录每个点的测量结果与停止原因，便于断点续跑与避免重复仿真。

补充：在大规模跑点时，更推荐将“推断/规划”和“执行”解耦：

- 脚本负责基于已有日志/manifest 推断区间与下一批点位（输出命令列表）；
- 你用 `bsub` 等调度系统执行这些命令产生日志；
- 脚本再次读取日志更新 manifest，并继续规划下一批点位。

---

## 4. 早停规则（建议落地到 C++ 或由 Python 外层近似）

characterization 常用三类停止条件（对每个横轴点）：

1. **失败达到上限即停止**：当失败帧数达到 $N_\text{fail,lim}$（例如 2 或 5）就停止。
   - 目的：在 $FER$ 很高时避免浪费（此时继续跑只是重复失败）。
2. **尾部无失败提前停止**：若连续若干个更差的点（例如更高 RBER）都无失败，且当前点已仿真达到少量帧数 $N_\text{min}$，则停止并继续扫更差/或直接收尾。
   - 目的：在 $FER$ 很低时避免为“凑够失败数”而把 max packets 打满。
3. **达到预设仿真帧数停止**：若已仿真 $N_\text{cw,target}$ 帧则停止。

在你们当前实现中，如果每点逻辑固定为“至少 10 个 error 或 max packets”，则第 1/2 条可能尚未生效。本文建议：将早停规则作为脚本/模型的后续增强点，因为它对“低 FER 区点位加密”是否可行影响很大。

---

## 5. AWGN / TAWGN 的具体选点策略（以 TheoRBER 视角）

### 5.1 第 0 轮：定位窗口

目标是找到一个区间，使得：

- 区间低端满足 $FER \gtrsim 0.9$（接近 1）
- 区间高端满足 $FER \lesssim 10^{-6}$（或到达你设定的低端目标）

可执行策略：

1. 从一个“较差信道”起点开始（高 RBER 或低 SNR），用粗步长扫（例如 SNR 步长 0.5 dB）。
2. 一旦遇到 $FER \le 0.9$ 的点，记为 $x_{0.9}$，将低端窗口设置为 $x_\text{low}$ 为其相邻更差的一个点（例如 SNR 减 0.1 dB，或 RBER 增一档）。
3. **防止粗步长跳过瀑布区（关键）**：若粗步长首次命中的 $x_{0.9}$ 已经“太好”（例如 $FER(x_{0.9})<0.1$），说明粗步长可能直接跨过瀑布区；此时应当在粗 bracket（上一个点 $x_\text{bad}$ 与当前点 $x_{0.9}$）内用更细步长回填（例如 0.1/0.05/0.025），直到找到一个更接近 $FER\approx 0.9$ 的起点。
4. 继续向“更好信道”方向扫，直到 $FER \le 10^{-6}$（或达到 0 fail 且上界足够小）。

实践建议（与你的经验一致）：若脚本的目的仅是“区间推断”，不必强行追到 $10^{-6}$，而是：

- 设一个 pilot 停止目标，例如 $FER \le 10^{-3}$；
- 并设置一个 SNR 跨度上限 `snr_span_cap`（例如 0.5 dB），从 $x_{0.9}$ 起最多向好信道推进 0.5 dB，避免 pilot 跑过头。

当出现 0 fail 时，可用简单上界估计：

- 若当前点仿真了 $N$ 帧且 0 fail，则 95% 上界近似 $FER \lesssim 3/N$。

用它替代“必须观测到 $10^{-6}$”能显著减少低 FER 端的盲目计算。

### 5.2 第 1..L 轮：窗口内分段步长（符合你的偏好）

你要求的经验规则是：当 FER 很小后，步长更细。

一个可落地的分段步长策略（以 SNR 为例）：

- 若 $FER > 10^{-4}$：$\Delta_\text{SNR}=0.1$
- 若 $10^{-5}<FER\le 10^{-4}$：$\Delta_\text{SNR}=0.05$
- 若 $FER \le 10^{-5}$：$\Delta_\text{SNR}=0.025$（你的经验规则）

并添加一个“跨 decade 加密”的保险：

- 若相邻两点满足 $|\log_{10}(FER_{i+1})-\log_{10}(FER_i)|>D$，在其间插点，直到每段跨越不超过 $D$ decade（推荐 $D=0.5$）。

注意：低 FER 区的统计不确定性更大（同样帧数下），即使曲线出现相邻点跳变一个 decade，也可能是合理现象。因此“加密规则”应优先基于预算与信息增益，而不是强行追求平滑。

## 6. ERR\_INJ 的具体选点策略（以 K 为横轴）

ERR\_INJ 只扫注入错误数 $K$，一般满足：

- $K$ 越大，FER 越高（但可能存在局部非单调）

建议的自动窗口定位：

1. 选一个足够大的 $K_\text{start}$（使得 $FER\approx 1$ 或至少 $>0.9$），粗步长向下扫（例如 $\Delta K=50$）。
2. 找到首次 $FER\le 0.9$ 的点，将其相邻更差点设为低端窗口（更大 K）。
3. 继续减小 K，直到 $FER\le 10^{-6}$ 或达到 0 fail 上界足够小。

窗口内加密建议：

- 在 $FER>10^{-5}$ 区域可用较粗的 $\Delta K$（例如 5 或 10）
- 在 $FER\le 10^{-5}$ 区域若你希望更精细地观察“纠错极限边缘”，可减到 $\Delta K=1$

由于你当前“不关心门限细节，只要覆盖区间”，通常保持较粗 $\Delta K$ 即可。

---

## 7. 多轮加深（looping）与缩窗（narrowing）

借鉴常见 C++ characterization philosophy：

1. 第 0 轮：每点仅跑很少帧数（例如 100 或 1000）得到粗曲线与窗口。
2. 第 1 轮：只跑窗口内点位，提高每点帧数（例如 1000 或 10000），推动曲线到 $10^{-5}$ 左右。
3. 第 2 轮：进一步缩窄窗口到低 FER 区（例如 $10^{-4}$ 以下），在预算允许时继续向 $10^{-6}$ 推进。

缩窗的一个直接做法：

- 只保留满足 $FER\in[10^{-2},10^{-6}]$ 的横轴区间，并在两端加少量 margin（例如多扩展 2 个步长）。

---

## 8. manifest 与目录规范（用于“去重 + 断点续跑”）

建议为每个 `case` 维护一个 manifest（CSV 或 JSON），每行一个点：

- `case_id`
- `model`（AWGN/TAWGN/ERR_INJ）
- `hre_bit`（若适用）
- `axis_type`（SNR/TheoRBER/K）
- `axis_value`
- `TheoRBER`、`RAW_BER`
- `LDPC_FER`
- `TotalPackets`、`FailCW`（若可读）
- `StopReason`（fail_limit / no_fail_tail / reached_target / max_packets）
- `LogPath`
- `Seed`

目录结构建议保持你当前的习惯：

- 顶层按码率/矩阵组织
- 其下按译码器/配置组织
- 若按 HREbit 分目录，则最后一级为 `0bit/1bit/.../70bit`

自动脚本在运行前应：

1. 扫描已有 log 并解析更新 manifest
2. 只对缺失点发起仿真

## 10. 建议的默认参数（可作为起始点）

以下参数不是“唯一正确”，但适合作为第 0 版可运行默认值：

- $FER_\text{hi}=0.9$
- $FER_\text{lo}=10^{-6}$
- pilot 粗扫步长：SNR 0.5 dB 或 K 50
- 窗口内步长（AWGN/TAWGN）：0.1 / 0.05 / 0.025（按 FER 分段）
- 窗口内步长（ERR\_INJ）：$\Delta K$=10（粗）/ 1（细，可选）
- 0 fail 上界判据：$3/N \le FER_\text{lo}$ 视为“足够低”

---

## 11. 风险与边界条件（保持怀疑）

1. 低 FER 区域点位加密并不必然提升真实性：若每点统计不足，曲线在 log 轴上出现大跳变是可能的，强行平滑可能掩盖真实的 error floor 结构。
2. 对 TAWGN（固定 FBC）而言，曲线物理意义是条件性能 $P(\text{fail}\mid FBC=k)$，与标准 AWGN FER 不同，选点策略应当明确目标指标。
3. 若你坚持每点必须观测到至少 10 fail，$FER\le 10^{-6}$ 的点会非常昂贵，点位加密可能不可承受；此时建议引入早停与上界判据。

---

## 12. 下一步落地建议（最小可行实现）

最小可行版本建议：

1. 先只做“第 0 轮 pilot 自动定位窗口 + 输出点位列表”，不强制多轮加深。
2. 将窗口与点位写入 manifest，并为每个 `case` 生成一个 `plan.json`（包含 $x_\text{low},x_\text{high},\Delta$ 分段策略）。
3. 后续再加多轮加深与早停策略。
